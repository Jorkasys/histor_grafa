# historian2grafana

Копирует значения тегов из **AVEVA Historian** в собственную базу данных раз в несколько
секунд и показывает по ней графики — на странице приложения и в **Grafana**.

![Страница «Загрузка»](docs/img/loading.png)

## Что умеет

- **Подключение к AVEVA Historian** через его SQL Server (база `Runtime`): логином SQL Server
  или учётной записью Windows. Историк только читается.
- **Выбор тегов масками** по таблице `Runtime.dbo.Tag`: `Lehmann1_*, CP2_*`, кроме `Sys*`.
  Новые теги подхватываются сами.
- **Проверка подключения по шагам**: вход, список тегов, чтение значений и оценка объёма данных.
- **Копирование раз в 5 секунд**: при первом запуске — история за заданное число часов, дальше —
  только новые значения. Без дублей; после перерыва пропущенное докопируется само.
- **Графики**: страница «Графики» в приложении и готовый дашборд Grafana «Теги историка».

## Два способа установки

| | Комплект без Docker | Docker Desktop |
|---|---|---|
| Когда подходит | **Компьютер без интернета**, виртуальная машина, нет прав администратора | Компьютер с интернетом, Docker Desktop уже есть |
| Что ставить на целевой компьютер | Ничего: одна папка, запуск `start.bat` | Docker Desktop (и WSL 2) |
| Права администратора | Не нужны | Нужны для установки Docker Desktop |
| Вход в историк учётной записью Windows | Как в SSMS — без ввода пароля, если компьютер в домене | Только с вводом `ДОМЕН\логин` и пароля |
| База данных | PostgreSQL 16 | PostgreSQL 16 + TimescaleDB (сжатие старых данных) |
| Инструкция | [ниже](#установка-на-компьютер-без-интернета) | [docs/INSTALL.md](docs/INSTALL.md) |

Страницы приложения, копирование и дашборд Grafana в обоих способах одинаковые.

## Установка на компьютер без интернета

Этот способ — для виртуальной машины или любого компьютера с Windows без доступа в интернет,
на который можно перенести файлы с другого компьютера (общая папка, буфер обмена удалённого
рабочего стола, флешка).

### Нужен ли Docker Desktop?

**Нет.** Для компьютера без интернета Docker Desktop — самый трудный путь:

- внутри виртуальной машины ему нужна **вложенная виртуализация** (WSL 2 внутри VM) — её
  включает администратор гипервизора, и на многих заводских виртуалках она выключена;
- без интернета приходится отдельно ставить WSL 2, сам Docker Desktop и переносить образы
  командами `docker save` / `docker load`;
- крупной компании для работы с Docker Desktop нужна платная подписка.

Вместо этого на компьютере с интернетом собирается **комплект** — одна папка, в которой уже
лежит всё: Python, PostgreSQL, Grafana и само приложение. На виртуалке её достаточно
распаковать и запустить `start.bat`. В Windows ничего не устанавливается, права администратора
не нужны, удалить — стереть папку.

### Что понадобится

| Где | Что |
|---|---|
| Компьютер с интернетом | Windows 10/11, PowerShell (есть в Windows), около 2 ГБ свободного места, эта папка проекта |
| Виртуалка без интернета | Windows 10/11 64-бит, около 2 ГБ свободного места плюс место под данные, сетевой доступ к серверу историка (TCP-порт 1433) |
| Учётная запись историка | Логин SQL Server с правом чтения базы `Runtime` **или** доменная учётная запись Windows, под которой вы входите в SSMS |

### Шаг 1. Собрать комплект (на компьютере с интернетом)

Откройте PowerShell в папке проекта (в Проводнике: адресная строка → `powershell` → Enter)
и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File offline\build-offline.ps1
```

Сценарий скачает около 600 МБ и через 5–15 минут соберёт архив
**`dist\historian2grafana-offline.zip`** (около 250 МБ). Что в нём:

| Папка или файл | Что это |
|---|---|
| `start.bat` | Запуск: база, Grafana и приложение |
| `stop.bat` | Остановка базы и Grafana |
| `check.bat` | Проверка связи с сервером историка |
| `.env.example` | Порты и пароли (при первом запуске копируется в `.env`) |
| `runtime\python` | Python 3.13 без установки, со всеми библиотеками приложения |
| `runtime\pgsql` | PostgreSQL 16 без установки |
| `runtime\grafana` | Grafana 11.6 без установки |
| `app`, `web`, `grafana`, `docker` | Само приложение, страницы, дашборд Grafana, настройки драйвера |

Если компьютер выходит в интернет через прокси и скачивание не идёт, скачайте три архива
вручную (браузером) в папку `dist\downloads` — с этими же именами — и запустите сценарий снова:
он возьмёт уже скачанное.

| Файл | Откуда |
|---|---|
| `python-3.13.16-embed-amd64.zip` | https://www.python.org/ftp/python/3.13.16/python-3.13.16-embed-amd64.zip |
| `postgresql-16.15-1-windows-x64-binaries.zip` | https://get.enterprisedb.com/postgresql/postgresql-16.15-1-windows-x64-binaries.zip |
| `grafana-11.6.0.windows-amd64.zip` | https://dl.grafana.com/oss/release/grafana-11.6.0.windows-amd64.zip |

Библиотеки Python сценарий всё равно скачивает сам (с pypi.org), поэтому доступ в интернет
из PowerShell нужен.

### Шаг 2. Перенести на виртуалку

1. Скопируйте на виртуалку **один файл** — `historian2grafana-offline.zip`.
2. Распакуйте его **прямо в `C:\`** (правый щелчок → «Извлечь все…» → `C:\`). Получится папка
   `C:\historian2grafana-offline`.

> **Важно.** Распаковывайте в короткий путь без русских букв и пробелов, например прямо в `C:\`.
> В Grafana много файлов с длинными именами: в глубокой папке Windows не сможет их распаковать,
> а PostgreSQL не любит русские буквы в пути к данным.

### Шаг 3. Запустить

Дважды щёлкните **`start.bat`** в папке `C:\historian2grafana-offline`. При первом запуске
создаётся база данных (около 10 секунд), затем запускаются PostgreSQL, Grafana и приложение,
и открывается браузер на **http://localhost:8000**. В окне будет примерно так:

```
historian2grafana — запуск

  Первый запуск: создаю базу данных в папке data\postgres…
  Запускаю PostgreSQL (порт 55432)…
  Запускаю Grafana (порт 3000)…

  Приложение:  http://localhost:8000
  Grafana:     http://localhost:3000

  Не закрывайте это окно, пока работаете. Остановить: Ctrl+C.
```

- **Окно не закрывайте**, пока приложение нужно: закрыли окно — копирование остановилось.
- Первый запуск Grafana занимает до минуты — если http://localhost:3000 сразу не открылся,
  подождите и обновите страницу.
- Если Windows спросит про **брандмауэр** для `python.exe` или `grafana.exe`: «Разрешить доступ»
  нужно, только если страницы будут открывать с других компьютеров. Для работы на самой
  виртуалке можно нажать «Отмена».
- Если появится синее окно **«Windows защитила ваш компьютер»** — «Подробнее» → «Выполнить в
  любом случае».

### Шаг 4. Проверить сеть до историка

Прежде чем вводить настройки, убедитесь, что сервер историка доступен с виртуалки. Откройте
командную строку в папке комплекта (адресная строка Проводника → `cmd` → Enter) и выполните
(вместо OKFFS800HIS01 — имя или IP-адрес вашего сервера):

```bat
check.bat OKFFS800HIS01 1433
```

Нужен ответ `✓ адрес …` и `✓ открыт`. Если имя не находится — попробуйте полное имя с доменом
или IP-адрес (их показывает `nslookup OKFFS800HIS01` или администратор). Если порт закрыт —
историк недоступен с виртуалки по сети: нужен доступ через брандмауэр.

### Шаг 5. Подключиться к историку

На странице **«Подключение»** (http://localhost:8000):

1. **Сервер историка** — как в SSMS (`OKFFS800HIS01`), полное имя или IP-адрес. **Порт** — пусто
   (1433). **База** — `Runtime`.
2. **Вход** — выберите один из вариантов:

   | Ситуация | Что выбрать и заполнить |
   |---|---|
   | Виртуалка в домене, вы вошли в Windows той же учётной записью, что в SSMS | «Учётная запись Windows», **логин и пароль оставьте пустыми** — приложение войдёт как вы, точно так же, как SSMS с «Windows Authentication» |
   | Виртуалка не в домене (или вы вошли в неё другой учётной записью) | «Учётная запись Windows», логин `EU\ваш_логин` и пароль от него |
   | Есть отдельный логин SQL Server | «Логин SQL Server», логин и пароль |

3. **Какие теги копировать** — для первой проверки несколько масок, например `Lehmann1_*`.
   Пусто — все теги, кроме `Sys*`. **Загрузить историю за последние** — например 24 часа.
4. **Проверить подключение** → все три шага должны быть зелёными.
5. **▶ Сохранить и начать копирование** — откроется страница «Загрузка».

Графики — на странице **«Графики»** приложения и в **Grafana: http://localhost:3000**
(дашборд «Теги историка» откроется сразу, вход не нужен). Подробно о страницах, Grafana и
сверке данных с SSMS — в [docs/INSTALL.md](docs/INSTALL.md), разделы 7–10.

> **Вход без пароля** работает только потому, что приложение запущено под вашей учётной
> записью Windows. Если `start.bat` запустит другой пользователь, в историк войдёт он.

### Повседневная работа

| Задача | Как |
|---|---|
| Запустить | `start.bat` |
| Остановить приложение | Ctrl+C в окне `start.bat` (на вопрос «Завершить выполнение пакетного файла?» ответьте `Y`) или просто закрыть окно |
| Остановить и базу, и Grafana | `stop.bat` (после закрытия окна они продолжают работать в фоне; следующий `start.bat` их подхватит) |
| Проверить подключение к историку с сохранёнными настройками | `check.bat` без параметров |
| Запускать при входе в Windows | Нажмите Win+R → `shell:startup` → Enter и положите в открывшуюся папку **ярлык** на `start.bat` |
| Порты и пароли | Файл `.env` в папке комплекта (открыть Блокнотом). После изменения — перезапустить `start.bat` |
| Журналы | Окно `start.bat`, файлы `data\postgres.log` и `data\grafana.log` |
| Начать с чистого листа | `stop.bat`, затем удалить папку `data` (настройки подключения и скопированные данные пропадут) |
| Обновить приложение | Собрать новый комплект, остановить старый (`stop.bat`), заменить все файлы, **кроме папки `data` и файла `.env`** |

Все данные — в папке **`data`**: база (`data\postgres`) и настройки Grafana (`data\grafana`).
Порты по умолчанию: приложение 8000, Grafana 3000, база 55432 (видна только с самой
виртуалки). Пароль базы (`DB_PASSWORD` в `.env`) действует только при первом запуске.

Обычный PostgreSQL не сжимает старые данные: одна строка занимает около 100 байт, то есть
1 млн строк в сутки — около 100 МБ в сутки. Сколько строк в сутки даст выбор тегов, показывает
проверка подключения; текущий размер — на странице «Загрузка».

### Если что-то не так

| Что видно | Что сделать |
|---|---|
| `ОШИБКА: порт … занят` | Порт занят другой программой — поменяйте `APP_PORT`, `GRAFANA_PORT` или `DB_PORT` в `.env` |
| `порт 8000 уже занят: приложение, вероятно, уже запущено` | Приложение уже открыто в другом окне `start.bat` — откройте http://localhost:8000 |
| `PostgreSQL не запустилась` | Смотрите строки под сообщением и `data\postgres.log`. Чаще всего — папка с русскими буквами в пути или без права записи: распакуйте комплект в `C:\` |
| Не найден `VCRUNTIME140.dll` или `MSVCP140.dll` | На виртуалке нет библиотек Visual C++. На компьютере с интернетом скачайте https://aka.ms/vs/17/release/vc_redist.x64.exe, перенесите и установите (нужны права администратора) |
| Ошибка при распаковке: слишком длинный путь | Распакуйте прямо в `C:\` |
| Grafana не открывается | Первый запуск Grafana занимает до минуты. Если и потом нет — `data\grafana.log` |
| Вход без пароля: `Login failed for user 'NT AUTHORITY\ANONYMOUS LOGON'` или «ненадёжный домен» | Виртуалка не в домене или вы вошли в неё не той учётной записью — укажите `EU\логин` и пароль или логин SQL Server |
| `Login failed for user …` (18456) | Неверный логин или пароль либо нет права читать базу `Runtime` |
| `сервер не отвечает` | Пройдите шаг 4: имя, порт, брандмауэр |
| Остальное | Таблицы неполадок в [docs/INSTALL.md](docs/INSTALL.md), раздел 14 — сообщения приложения там те же |

### Если всё-таки нужен Docker на виртуалке

Возможно, но сложнее: администратор гипервизора должен включить для виртуалки вложенную
виртуализацию (Hyper-V: `Set-VMProcessor -VMName <имя> -ExposeVirtualizationExtensions $true`;
VMware: «Virtualize Intel VT-x/EPT or AMD-V/RVI»), затем на виртуалку переносятся и ставятся
WSL 2 (файл `wsl.<версия>.x64.msi` со страницы https://github.com/microsoft/WSL/releases) и
установщик Docker Desktop, а образы приложения — файлом, как описано в
[docs/INSTALL.md](docs/INSTALL.md), раздел 13. Для проверки на виртуалке комплект без Docker
проще и надёжнее.

## Установка через Docker Desktop (компьютер с интернетом)

```powershell
git clone <адрес этого репозитория> C:\historian2grafana
cd C:\historian2grafana
Copy-Item .env.example .env
docker compose up -d --build
```

1. Откройте **http://localhost:8000** → «Подключение»: сервер историка, логин и пароль, маски тегов.
2. **Проверить подключение** → **Сохранить и начать копирование**.
3. Графики — на странице «Графики» или в Grafana: **http://localhost:3000**.

Подробная инструкция — от установки Docker Desktop до решения проблем:
[docs/INSTALL.md](docs/INSTALL.md) (то же в Word: `docs/Инструкция.docx`).

| Контейнер | Что делает | Адрес |
|---|---|---|
| `h2g-app` | Подключение к историку, копирование, страницы в браузере | http://localhost:8000 |
| `h2g-db` | PostgreSQL 16 + TimescaleDB: теги и их значения | — |
| `h2g-grafana` | Grafana с дашбордом «Теги историка» | http://localhost:3000 |

## Для разработчиков

Приложение — Python 3.12+ (FastAPI, asyncpg), страницы — HTML и JavaScript без сборки.
Комплект без Docker собирает `offline/build-offline.ps1`, запускает его `offline/launcher.py`.

```powershell
pip install -r requirements.txt -r requirements-dev.txt
pytest
```

Тестам с базой нужен PostgreSQL: адрес задаётся переменными `TEST_DB_HOST`, `TEST_DB_PORT`,
`TEST_DB_USER`, `TEST_DB_PASSWORD`; без него эти тесты пропускаются. Историк в тестах
заменяет эмулятор на SQLite с таблицами того же вида, что в `Runtime`.
